# Проектная работа "Веб-ларек"

Стек: HTML, SCSS, TS, Vite

Структура проекта:
- src/ — исходные файлы проекта
- src/components/ — папка с JS компонентами
- src/components/base/ — папка с базовым кодом

Важные файлы:
- index.html — HTML-файл главной страницы
- src/types/index.ts — файл с типами
- src/main.ts — точка входа приложения
- src/scss/styles.scss — корневой файл стилей
- src/utils/constants.ts — файл с константами
- src/utils/utils.ts — файл с утилитами

Компоненты приложения:

- `src/components/base/` — базовые `Component`, `Api` и `EventEmitter`;
- `src/components/Models/` — модели каталога, корзины и покупателя;
- `src/components/View/` — компоненты представления страницы, карточек, корзины, модального окна, форм и результата заказа;
- `src/components/API/` — адаптер API интернет-магазина;
- `src/types/` — типы предметной области и сетевых запросов;
- `src/main.ts` — точка композиции и функциональный презентер приложения.

# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Принципы организации кода

- модели `Catalog`, `Basket` и `Buyer` имеют разные зоны ответственности и не обращаются к DOM или API;
- компоненты View не хранят состояние предметной области и работают только со своим корневым DOM-контейнером и его дочерними элементами;
- все используемые компонентом элементы разметки находятся один раз в конструкторе и сохраняются в полях;
- общий код карточек вынесен в `Card<T>`, общий код форм — в `Form<T>`, операции поиска и клонирования DOM-элементов — в утилиты;
- модели и представления не содержат ссылок друг на друга: их взаимодействие координирует презентер через `EventEmitter`;
- сетевые запросы выполняет только `WebLarekApi`; он использует базовый `Api` через композицию и не связан с моделями или представлениями;
- презентер получает данные через публичные методы моделей и подготавливает отдельные структуры отображения для View.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

Дополнительные методы `EventEmitter`:

- `off(eventName: EventName, callback: Function): void` — удаляет указанную подписку;
- `onAll(callback: (event: EmitterEvent) => void): void` — подписывает обработчик на все события;
- `offAll(): void` — удаляет все установленные подписки.

## Данные


Товар:

```
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}
```

- id: string - ID товара
- description: string - описание
- image: string - путь к изображению
- title: string - название
- category: string - категория
- price: number | null - цена или `null`, если товар недоступен

Покупатель:

```
interface IBuyer {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}
```

- payment: TPayment - выбранный способ оплаты
- email: string TBuyerErrors - email покупателя
- phone: string - номер телефона
- address: string - адрес доставки

Остальные типы приложения:

```ts
type ApiPostMethods = 'POST' | 'PUT' | 'DELETE';
type TPayment = 'card' | 'cash' | '';
type TBuyerErrors = Partial<Record<keyof IBuyer, string>>;

interface IApi {
  get<T extends object>(uri: string): Promise<T>;
  post<T extends object>(uri: string, data: object, method?: ApiPostMethods): Promise<T>;
}

interface IProductsResponse {
  total: number;
  items: IProduct[];
}

interface IOrder extends IBuyer {
  total: number;
  items: string[];
}

interface IOrderResponse {
  id: string;
  total: number;
}
```

- ApiPostMethods — допустимые методы запросов, изменяющих данные;
- TPayment — способ оплаты: онлайн, при получении или отсутствие выбора;
- TBuyerErrors — объект сообщений об ошибках, ключи которого соответствуют полям покупателя;
- IApi — программный интерфейс транспорта API;
- IProductsResponse — ответ сервера со списком товаров и их количеством;
- IOrder — отправляемый заказ: данные покупателя, итоговая стоимость и массив идентификаторов товаров;
- IOrderResponse — ответ сервера с идентификатором и стоимостью оформленного заказа.

## Модели данных

### Класс Catalog

Класс отвечает за хранение каталога товаров и товара, выбранного пользователем для подробного просмотра. Модель не отвечает за отображение товаров и работу с разметкой.

Конструктор constructor(events: IEvents) принимает брокер событий и создаёт пустой каталог без выбранного товара.

Служебное поле events: IEvents хранит брокер событий. Поле products: IProduct[] содержит каталог, поле preview: IProduct | null — выбранный товар или null.

Поля:

- products: IProduct[] - товары, полученные с сервера
- preview: IProduct - товар, выбранный для отображения

Методы:

- setProducts(products: IProduct[]) сохраняет массив в каталоге и создаёт событие catalog:changed
- getProducts(): IProduct[] возвращает массив товаров каталога
- getProduct(id: string): IProduct | undefined возвращает товар по его идентификатору либо undefined
- setPreview(product: IProduct): void сохраняет товар, выбранный для подробного отображения, и создаёт событие preview:changed
- getPreview(): IProduct | null возвращает товар, выбранный для подробного отображения

### Класс Basket

Отвечает за хранение товаров, выбранных покупателем, а также за вычисление количества и общей стоимости товаров в корзине.

Конструктор constructor(events: IEvents) принимает брокер событий и создаёт пустую корзину.

Поле items: IProduct[] хранит выбранные товары, служебное поле events: IEvents — брокер событий.

Поля класса:

- items: IProduct[] - массив товаров, добавленных покупателем в корзину.

Методы класса:

- getItems(): IProduct[] возвращает массив товаров в корзине
- addItem(product: IProduct): void добавляет товар в корзину и создаёт событие basket:changed
- removeItem(product: IProduct): void удаляет товар из корзины и создаёт событие basket:changed
- clear(): void удаляет из корзины все товары и создаёт событие basket:changed
- getTotal(): number возвращает общую стоимость товаров в корзине
- getCount(): number возвращает количество товаров в корзине
- hasItem(id: string): boolean возвращает true, если товар находится в корзине, иначе возвращает false

### Класс Buyer

Отвечает за хранение и изменение данных покупателя

Конструктор constructor(events: IEvents) принимает брокер событий и создаёт модель с пустыми контактными данными, адресом и невыбранным способом оплаты.

Поля payment: TPayment, email: string, phone: string и address: string хранят данные покупателя. Служебное поле events: IEvents хранит брокер событий.

Поля:

- payment: TPayment - выбранный способ оплаты
- email: string - адрес электронной почты 
- phone: string - номер телефона 
- address: string - адрес доставки

Методы:

- setData(data: Partial<IBuyer>): void сохраняет переданные данные покупателя и создаёт событие buyer:changed
- getData(): IBuyer возвращает все сохранённые данные покупателя
- clear(): void очищает все данные покупателя, сбрасывает способ оплаты и создаёт событие buyer:changed
- validate(): TBuyerErrors проверяет данные покупателя и возвращает объект ошибок

## Слой коммуникации

### Класс WebLarekApi

Отвечает за взаимодействие приложения с сервером

Конструктор принимает объект для выполнения запросов:

- api: IApi - экземпляр класса для работы с api

Поля:

- api: IApi - объект, с помощью которого выполняются запросы к серверу

Методы:

## Слой представления

Все классы представления наследуются от Component<T>. Они получают уже подготовленные презентером данные, изменяют только свои DOM-элементы и сообщают о действиях пользователя через IEvents. Представления не обращаются к моделям и API напрямую.

Для передачи данных компонентам используются отдельные типы отображения. Они не изменяют типы и модели слоя данных:

- ICardData — название, категория, изображение и цена карточки каталога;
- IPreviewCardData — данные карточки каталога, описание и состояние кнопки подробного просмотра;
- IBasketCardData — порядковый номер, название и цена позиции корзины;
- IPageData — массив готовых элементов каталога и значение счётчика корзины;
- IBasketData — массив готовых элементов корзины, итоговая стоимость и признак доступности оформления;
- IFormData — валидность формы и массив сообщений об ошибках;
- IOrderFormData — данные базовой формы, способ оплаты и адрес;
- IContactsFormData — данные базовой формы, почта и телефон;
- ISuccessData — итоговая сумма выполненного заказа;
- IModalData — готовый DOM-элемент, который требуется показать в модальном окне.

```ts
interface ICardData {
  title: string;
  category: string;
  image: string;
  price: number | null;
}

interface IPreviewCardData extends ICardData {
  description: string;
  buttonText: string;
  buttonDisabled: boolean;
}

interface IBasketCardData {
  index: number;
  title: string;
  price: number | null;
}

interface IPageData {
  catalog: HTMLElement[];
  counter: number;
}

interface IBasketData {
  items: HTMLElement[];
  total: number;
  valid: boolean;
}

interface IFormData {
  valid: boolean;
  errors: string[];
}

interface IOrderFormData extends IFormData {
  payment: TPayment;
  address: string;
}

interface IContactsFormData extends IFormData {
  email: string;
  phone: string;
}

interface ISuccessData {
  total: number;
}

interface IModalData {
  content: HTMLElement;
}

interface IProductEvent {
  id: string;
}

interface IBuyerChangeEvent {
  field: keyof IBuyer;
  value: string;
}
```

Все прикладные интерфейсы и типы предметной области, отображения и событий объявлены в едином файле src/types/index.ts. IProductEvent описывает события выбора и удаления товара, а IBuyerChangeEvent — изменение поля данных покупателя. Локальные дубликаты этих структур в компонентах отсутствуют.

### Класс Page

Отвечает за каталог на главной странице и счётчик корзины в шапке.

Конструктор constructor(container: HTMLElement, events: IEvents) принимает элемент .page__wrapper и брокер событий. Все управляемые элементы ищутся только внутри этого контейнера.

Поля:

- galleryElement: HTMLElement — контейнер каталога .gallery;
- basketButton: HTMLButtonElement — кнопка открытия корзины;
- counterElement: HTMLElement — элемент счётчика товаров.

Сеттеры:

- catalog: HTMLElement[] заменяет содержимое галереи карточками;
- counter: number отображает число товаров в корзине.

При нажатии на иконку корзины создаёт событие basket:open.

### Классы карточек

Абстрактный класс Card<T> — общий непосредственный родитель всех трёх классов карточек. В него вынесены поиск общих DOM-элементов и сеттеры названия, цены, категории и изображения. Его поля titleElement, priceElement, categoryElement и imageElement содержат соответствующие элементы карточки. Элементы категории и изображения опциональны, поскольку их нет в шаблоне позиции корзины. Конструктор принимает корневой элемент карточки.

Конструктор constructor(container: HTMLElement) сохраняет корневой элемент и находит элементы карточки. Сеттеры title: string, price: number | null, category: string и image: string изменяют соответствующую часть разметки. Метод render(data?: Partial<T>): HTMLElement наследуется от Component<T>.

- CatalogCard отвечает за шаблон #card-catalog и отображает товар в каталоге. При клике создаёт событие catalog:select с идентификатором товара;
- PreviewCard отвечает за шаблон #card-preview и отображает изображение, категорию, название, описание, цену и состояние кнопки подробного просмотра. Поля descriptionElement и actionButton содержат описание и кнопку действия. При клике на кнопку создаёт событие preview:toggle;
- BasketCard отвечает за шаблон #card-basket и отображает номер позиции, название и цену товара. Поля indexElement и deleteButton содержат порядковый номер и кнопку удаления. При клике создаёт событие basket:remove с идентификатором товара.

Конструктор каждой конечной карточки принимает корневой элемент клонированного шаблона и брокер событий. CatalogCard и BasketCard также получают идентификатор, который замыкается обработчиком клика и не сохраняется в поле класса. Слушатели устанавливаются один раз в конструкторах, а события генерируются самими компонентами View.

Точные сигнатуры конструкторов:

- CatalogCard(container: HTMLElement, events: IEvents, id: string);
- PreviewCard(container: HTMLElement, events: IEvents);
- BasketCard(container: HTMLElement, events: IEvents, id: string).

Дополнительные сеттеры PreviewCard: description: string, buttonText: string, buttonDisabled: boolean. Дополнительный сеттер BasketCard: index: number.

### Класс BasketView

Отвечает за содержимое корзины.

Конструктор constructor(container: HTMLElement, events: IEvents) принимает элемент из шаблона #basket и брокер событий.

Поля:

- listElement: HTMLElement — список товаров;
- totalElement: HTMLElement — общая стоимость;
- orderButton: HTMLButtonElement — кнопка перехода к оформлению.

Сеттеры:

- items: HTMLElement[] отображает карточки выбранных товаров;
- total: number отображает общую стоимость;
- valid: boolean управляет доступностью кнопки оформления.

При нажатии на кнопку оформления создаёт событие basket:order. Надпись о пустой корзине отображается стилями при отсутствии элементов списка.

### Класс Modal

Управляет единым модальным окном приложения.

Конструктор constructor(container: HTMLElement, events: IEvents) принимает #modal-container и брокер событий. Класс поддерживает закрытие по крестику и клику по оверлею.

Поля:

- contentElement: HTMLElement — контейнер для самостоятельного компонента, показанного внутри окна;
- closeButton: HTMLButtonElement — кнопка закрытия.

Modal является самостоятельным конечным компонентом: у него нет дочерних классов. Корзина, карточка подробного просмотра, формы и сообщение об успехе не наследуются от него. Презентер передаёт их готовые DOM-элементы через сеттер content, поэтому эти компоненты при необходимости можно вывести и вне модального окна.

Методы и сеттеры:

- content: HTMLElement помещает переданный компонент в модальное окно;
- open(): void открывает окно;
- close(): void закрывает окно и очищает содержимое;
- render(data: Partial<IModalData>): HTMLElement отображает содержимое и открывает окно.

Клики по крестику и оверлею создают событие modal:close. Презентер обрабатывает его и вызывает метод close(). При открытом окне прокрутка страницы блокируется стилями.

### Абстрактный класс Form

Абстрактный базовый класс форм заказа. Напрямую не создаётся, а предоставляет общую реализацию обработки ввода, отправки, валидности и ошибок для OrderForm и ContactsForm.

Конструктор constructor(container: HTMLFormElement, events: IEvents, submitEvent: string) принимает форму, брокер событий и имя события отправки.

Поля:

- submitButton: HTMLButtonElement — кнопка отправки формы;
- errorsElement: HTMLElement — область сообщений валидации.

Сеттеры:

- valid: boolean управляет доступностью кнопки отправки;
- errors: string[] отображает сообщения в .form__errors.

При изменении поля создаёт событие buyer:change с именем поля и значением.

### Класс OrderForm

Наследуется от Form<IOrderFormData> и представляет первый шаг оформления из шаблона #order. Поля paymentButtons и addressInput содержат кнопки способов оплаты и поле адреса. Сеттеры payment и address отображают полученные от презентера значения. Выбор способа оплаты создаёт событие buyer:change, а отправка формы — order:submit.

Конструктор constructor(container: HTMLFormElement, events: IEvents) передаёт базовой форме имя события отправки. Сеттеры payment: TPayment и address: string отображают выбранную оплату и адрес.

### Класс ContactsForm

Наследуется от Form<IContactsFormData> и представляет второй шаг оформления из шаблона #contacts. Поля emailInput и phoneInput содержат соответствующие элементы ввода, а одноимённые сеттеры отображают полученные от презентера значения. Изменение любого поля создаёт событие buyer:change, отправка формы — contacts:submit.

Конструктор constructor(container: HTMLFormElement, events: IEvents) передаёт базовой форме имя события отправки. Сеттеры email: string и phone: string отображают контактные данные.

### Класс Success

Отвечает за шаблон #success и отображает итог успешно оформленного заказа. Поля descriptionElement и closeButton содержат элемент с итогом и кнопку закрытия. Сеттер total: number выводит списанную сумму. При нажатии на кнопку закрытия создаёт событие success:close.

Конструктор constructor(container: HTMLElement, events: IEvents) находит элементы результата и устанавливает обработчик кнопки. Метод render(data?: Partial<ISuccessData>): HTMLElement наследуется от Component<ISuccessData>.

## Презентер

Для проекта выбран функциональный вариант презентера в src/main.ts, поскольку приложение состоит из одной страницы. Отдельный класс презентера не создаётся. Основной скрипт является точкой композиции: создаёт общий EventEmitter, модели, API и компоненты представления, после чего регистрирует обработчики событий.

Презентер не генерирует события. События создаются моделями при изменении данных и представлениями при действиях пользователя. Обработчики событий View изменяют модели, открывают модальные окна или отправляют запрос. Компоненты с данными перерисовываются в обработчиках событий моделей. Дополнительная отрисовка выполняется только при открытии нового содержимого модального окна.

Обработка изменений моделей устроена следующим образом:

- catalog:changed — презентер получает товары через Catalog.getProducts(), создаёт для каждого CatalogCard и передаёт готовые элементы компоненту Page;
- preview:changed — получает выбранный товар через Catalog.getPreview(), объединяет его состояние с результатом Basket.hasItem() и открывает PreviewCard;
- basket:changed — получает позиции, количество и стоимость методами Basket, создаёт BasketCard для каждой позиции и обновляет корзину и счётчик;
- buyer:changed — получает значения через Buyer.getData(), ошибки через Buyer.validate() и обновляет обе формы.

При оформлении заказа презентер объединяет данные разных моделей: получает реквизиты покупателя из Buyer, стоимость и идентификаторы товаров из Basket, формирует объект IOrder и передаёт его в WebLarekApi.createOrder(). После успешного ответа очищает модели, а их события обновляют зависимые представления. Затем презентер показывает компонент успешного заказа.

## События приложения

Каждое пользовательское действие в компонентах View приводит к генерации события. Обработчики событий находятся в презентере:

События моделей данных:

- catalog:changed — модель Catalog сохранила новый список товаров; данных не передаёт, актуальный каталог запрашивается презентером через getProducts();
- preview:changed — модель Catalog сохранила выбранный товар; данных не передаёт, товар запрашивается через getPreview();
- basket:changed — состав корзины изменился после добавления, удаления или очистки; данных не передаёт, актуальные товары, количество и стоимость запрашиваются методами Basket;
- buyer:changed — модель Buyer сохранила или очистила данные покупателя; данных не передаёт, актуальные значения и ошибки запрашиваются через getData() и validate().

События представлений:

- catalog:select — пользователь нажал на карточку каталога. Передаёт { id: string }; презентер получает товар из Catalog и открывает подробный просмотр;
- preview:toggle — пользователь нажал на кнопку карточки подробного просмотра. Данных не передаёт; презентер получает выбранный товар из Catalog и добавляет его в Basket либо удаляет из неё;
- basket:open — пользователь нажал на иконку корзины. Данных не передаёт; презентер собирает данные корзины и открывает соответствующий компонент;
- basket:remove — пользователь нажал на кнопку удаления позиции. Передаёт { id: string }; презентер удаляет товар из модели корзины и повторно отображает её;
- basket:order — пользователь нажал «Оформить». Данных не передаёт; презентер показывает первый шаг оформления;
- buyer:change — пользователь изменил поле формы или выбрал способ оплаты. Передаёт { field: string, value: string }; презентер сохраняет значение в Buyer, запрашивает результат валидации и обновляет форму;
- order:submit — пользователь отправил форму способа оплаты и адреса. Данных не передаёт; презентер проверяет первый шаг и показывает форму контактов;
- contacts:submit — пользователь отправил форму контактов. Данных не передаёт; презентер валидирует данные, формирует заказ из данных Buyer и Basket и передаёт его API;
- modal:close — пользователь нажал на крестик или оверлей. Данных не передаёт; презентер закрывает модальное окно;
- success:close — пользователь нажал кнопку в сообщении об успешном заказе. Данных не передаёт; презентер закрывает модальное окно.

Таким образом, обработчики DOM внутри View только формируют события. Решения об изменении каталога, корзины, данных покупателя, переходе между шагами и отправке заказа принимает презентер.
